## 踩坑与修复 (全部已 commit)

1. **pip 22.0 不支持 PEP 660** — `pip install -e .` 报 build_editable 缺失。→ 先 `pip install -U pip`。
2. **inventory 占位 IP + ssh 到自身被拒** — preflight 全 255。→ 实测值入 inventory; 自己的 pubkey 进自己的 authorized_keys。
3. **权重目录名 ≠ 模型语义名** — `/raid/model_hub/GLM-5.2-FP8` vs `name: glm-5.2`, 渲染出的 --model-path 不存在。→ `ModelSpec.local_dir` (`2b4ff64`)。
4. **镜像 UNPINNED** — 模板 fallback `tokiln/sglang-glm52:dev` 不存在。→ 验证 nightly 支持 GlmMoeDsa 后 pin 进 VERSIONS.lock (`247cc33`)。
5. **残留 dynamo.frontend 占 8000** — 7 天前的进程, worker 早没了。→ 清理; GPU 残留判定用 `nvidia-smi --query-compute-apps`。
6. **streaming 探针误报 FAIL** — GLM-5.2 思考阶段所有 delta 都在 `reasoning_content`, 探针只数 `content` → chunks=0。→ 两者都算 (`f1ac6b5`)。
7. **tool_calls 恒为空但 finish_reason=tool_calls** — 配置 glm45 被 sglang 映射到已废弃的 glm, 解析不了 GLM-5.2 的 `<tool_call>name<arg_key>k</arg_key><arg_value>v</arg_value>` 格式; server 端模板 auto-detect 明确给出 glm47。→ `tool_call_parser: glm47` (`f1ac6b5`)。**教训: probe 断言结构化字段 (而非裸文本) 正是为了抓这种半坏状态。**
8. **cancel 探针 15s grace 过严** — 实测断开后 sglang ~35-40s 才 abort (有界, 非泄漏)。→ 60s grace + 报告实测 drain_s (`cd59557`)。
9. **aa-loadgen 误报 82% err** — 判 ok 条件是收到过 `delta.content`; 短回复 (60% 请求 osl 20-120) 全程只有 reasoning_content → ttft=None → err。且失败原因被完全吞掉, 只有裸计数。→ reasoning 兼容 + `err_reasons` 前缀聚类进报告 (aa-loadgen `23d4e1c` 后续 commit)。
10. **report KEYS 契约漂移** — `ttft_p95`/`req_ok` vs 实际 `ttft_p95_s`/`requests_ok`, 报表一半 None。→ 对齐 + 契约测试固化 (`1894ea2`)。
